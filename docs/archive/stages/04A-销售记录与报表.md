## 1. 目标

阶段 03 打通了「卖出」动作（扫码收银 + 离线结算）。本阶段让老板能**看到经营数据**：
- 每天卖了多少钱、多少单、多少件；
- 翻看每一笔销售流水与单据明细；
- 一眼看到近 7 天的热销款，指导补货与上新。

数据已经在数据库里（`SaleOrder` / `SaleItem`），本阶段主要是**查询聚合 + 展示**，不改动核心交易逻辑。

---

## 2. 接口设计（后端，全部需登录，按门店隔离）

| 方法 | 路径 | 说明 |
|------|------|------|
| GET | `/api/v1/sales` | 销售流水（最近 100 笔），含明细名称、操作人、件数 |
| GET | `/api/v1/sales/summary` | 报表汇总：今日/本周 窗口指标 + 近 7 天热销 TOP5 |
| GET | `/api/v1/sales/:id` | 单据详情（明细行含商品名/颜色/尺码/条码/图） |

> 路由声明顺序：`summary` 在 `:id` 之前，避免 `summary` 被当作 id 捕获。

聚合实现要点（`sales.service.ts`）：
- **窗口指标**：`saleOrder.aggregate`（营业额 `_sum.totalAmount` + 单数 `_count`）+ `saleItem.aggregate`（件数 `_sum.quantity`，用关系过滤 `order: {shopId,status,createdAt}`）。
- **热销榜**：`saleItem.groupBy(by: skuId)` 按销量倒序取 5，再批量取 SKU/商品名拼装。
- **时间边界**：服务端本地时区「今日 0 点」「本周一 0 点」（周一为一周起点）。
- 只统计 `status = completed` 的单。

响应类型集中在共享包，前后端共用：`SaleOrderDetail` / `SaleItemDetail` / `SalesSummary` / `SalesWindowStats` / `TopSkuStat`（`packages/shared/src/sale.ts`）。

## 5. 已知限制 / 后续
- 报表为「实时查询聚合」，门店单量很大时后续可加按天预聚合表或缓存。
- 「热销榜」固定近 7 天 TOP5；后续可做时间范围筛选与导出。
- 销售记录页目前依赖联网获取（在线查看）；离线浏览历史可在后续接入本地缓存。
- 退货/作废（`voided`）尚未在 UI 提供，后续阶段补。
