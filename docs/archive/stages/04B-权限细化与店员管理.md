# 阶段 04B · 权限细化与店员管理

> 状态：✅ 已完成自我检查 + 真实数据库端到端验证
> 日期：2026-06-09
> 范围：店主（owner）/ 店员（staff）能力区分（后端守卫 + 前端隐藏），店员账号管理页

---

## 1. 目标

让账号分工清晰、数据安全：
- **店员**：日常收银（扫码 + 开单）、查看商品；看不到经营报表、不能建档/改价、不能管理账号。
- **店主**：全部权限，含建档、报表、店员管理。

权限以**后端守卫为准**（前端隐藏只是体验优化，不能作为安全边界）。

---

## 2. 权限矩阵

| 能力 | 接口 | 店主 owner | 店员 staff |
|------|------|:---:|:---:|
| 登录/查看自己 | `POST /auth/login`、`GET /auth/me` | ✅ | ✅ |
| 扫码匹配 | `GET /skus/by-barcode/:barcode` | ✅ | ✅ |
| 拉取商品（离线同步用） | `GET /products` | ✅ | ✅ |
| 开单收银 | `POST /sales` | ✅ | ✅ |
| 建档 | `POST /products` | ✅ | ❌ 403 |
| 上传图片 | `POST /uploads` | ✅ | ❌ 403 |
| 销售流水/详情 | `GET /sales`、`GET /sales/:id` | ✅ | ❌ 403 |
| 报表汇总 | `GET /sales/summary` | ✅ | ❌ 403 |
| 店员列表/新增 | `GET /auth/staff`、`POST /auth/staff` | ✅ | ❌ 403 |

> 注意：`GET /products` 对店员开放，因为离线同步引擎（拉取目录到本地缓存）依赖它，店员收银必须能用。

---

## 3. 实现方式

复用阶段 01 已有的 `RolesGuard` + `@Roles()`（基于 JWT 中的 `role`）：
- 在控制器 `@UseGuards(JwtAuthGuard, RolesGuard)`；
- 仅在「店主专属」的处理方法上加 `@Roles("owner")`；
- 未标注 `@Roles` 的方法对任意登录用户放行（守卫无元数据即放行）。

### 新增/改动文件

**后端 `apps/server`**
- `src/products/products.controller.ts`：控制器加 `RolesGuard`；`POST /products` 加 `@Roles("owner")`，`GET` 路由保持对店员开放。
- `src/uploads/uploads.controller.ts`：加 `RolesGuard` + `@Roles("owner")`。
- `src/sales/sales.controller.ts`：加 `RolesGuard`；`GET`（list/summary/:id）加 `@Roles("owner")`，`POST /sales` 对店员开放。
- `src/auth/auth.controller.ts`：新增 `GET /auth/staff`（店主专属）。
- `src/auth/auth.service.ts`：新增 `listMembers(shopId)`（返回成员，剔除密码）。
- `src/auth/auth.service.spec.ts`：新增 `createStaff`、`listMembers` 2 项单测。

**共享包 `packages/shared`**
- `src/auth.ts`：新增 `ShopMember` 类型。

**移动端 `apps/mobile`**
- `src/api.ts`：新增 `apiListStaff` / `apiCreateStaff`。
- `src/screens/StaffScreen.tsx`：店员管理页（新增店员表单 + 成员列表，下拉刷新）。
- `src/screens/HomeScreen.tsx`：按 `role` 隐藏店主专属入口（今日营业额卡、建档、销售记录/报表、店员管理）；店员仅见「扫码收银 / 商品列表」。报表数据店员不请求。
- `App.tsx`：新增 `staff` 路由。
