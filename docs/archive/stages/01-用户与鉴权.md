# 阶段 01 · 用户与鉴权（Auth）

> 状态：✅ 已完成并通过自我检查  
> 日期：2026-06-08  
> 范围：后端 NestJS 鉴权 + 移动端登录/会话 + 共享类型

---

## 1. 目标

替换脚手架阶段「用 `shopId` 查询参数」的临时做法，建立真正的多用户/门店鉴权基础：

- 注册（开通门店 + 创建老板账号）
- 登录（手机号 + 密码，返回 JWT）
- 会话保持（移动端持久化 token，启动时自动恢复登录）
- 角色权限（老板 owner / 店员 staff）
- 所有业务接口改为从登录态获取 `shopId` / `operatorId`，并做门店数据隔离

---

## 2. 关键设计决策

| 决策 | 选择 | 理由 |
|------|------|------|
| 密码哈希 | `bcryptjs`（纯 JS） | 无需原生编译，Windows/零基础环境零障碍 |
| 令牌 | JWT（`@nestjs/jwt`），有效期 30 天 | 无状态、移动端友好 |
| 鉴权实现 | 自定义 `JwtAuthGuard`（不引入 passport） | 依赖更少、更易理解 |
| 移动端 token 存储 | `expo-secure-store` | 加密存储，比 AsyncStorage 安全 |
| 数据隔离 | 业务查询强制带 `shopId` 校验 | 防止越权访问/销售他店商品 |
| 校验 | 共享包 Zod schema（前后端复用） | 单一事实来源，AI 友好 |

## 4. 接口一览（鉴权相关）

| 方法 | 路径 | 鉴权 | 说明 |
|------|------|------|------|
| POST | `/api/v1/auth/register` | 否 | 开通门店 + 创建老板 |
| POST | `/api/v1/auth/login` | 否 | 登录，返回 `{ token, user }` |
| GET | `/api/v1/auth/me` | 是 | 获取当前登录用户 |
| POST | `/api/v1/auth/staff` | 是（仅 owner） | 创建店员账号 |

业务接口（`/products`、`/skus/by-barcode/:barcode`、`/sales`）现均需 `Authorization: Bearer <token>`。
