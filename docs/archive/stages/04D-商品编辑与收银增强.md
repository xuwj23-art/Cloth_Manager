## 1. 商品可编辑（#1）

商品列表点任意商品进入「编辑商品」页，支持：
- 修改**商品名称**；
- 逐 SKU 修改**售价**与**库存**；
- 一键**下架 / 恢复在售**。

库存修改采用「盘点目标值」语义：与现有库存的差额会自动写入一条 `adjust` 库存流水（保留账目可追溯），并递增 SKU `version`（与同步乐观锁一致）。

- 后端：`PATCH /products/:id`（`@Roles("owner")`），入参 `UpdateProductInput { name?, coverImage?, skus?: [{ id, costPrice?, salePrice?, stock? }] }`。
- 移动端：`EditProductScreen`；`ProductsScreen` 卡片可点进入编辑。

## 2. 库存为 0 的处理策略（#2，方案 A：售罄自动归档）

**不做物理删除**（销售单 `SaleItem`、库存流水 `StockMovement` 均引用 SKU，物理删会破坏历史账与报表）。改为**软下架/归档**：

- 数据模型：`Product.archivedAt`（`null` = 在售）。
- **售罄自动归档**：任意销售导致某商品**总库存归零**时，事务内自动写 `archivedAt`，从「在售」列表收起到「已售罄」。
- **自动恢复**：通过编辑盘点把库存调回 > 0 时自动清除 `archivedAt`，重新在售。
- **手动**：店主可在编辑页手动「下架 / 恢复」（`POST /products/:id/archive` `/unarchive`）。
- 列表查询 `GET /products?scope=active|archived|all`（默认 `active`）；移动端商品列表顶部「在售 / 已售罄」分页切换。

> 选择理由：面向个体杂款店，款式多为一次性、卖完很少补货，自动收起售罄款可让在售列表保持清爽，同时完整保留历史账与报表，且随时可翻看/恢复。

## 3. 扫码音效（#3）

- 依赖 `expo-audio`；提示音资源 `apps/mobile/assets/beep.wav` 由 `tools/gen-beep.js` 合成（1320Hz、120ms、带淡入淡出避免爆音）。
- 扫码/手动查找命中 SKU 时：**先「嘀」声 + 成功震动**，再弹出确认卡；未命中时为错误震动 + 提示卡。

## 4. 手电筒 / 补光开关（#4）

- 收银相机右下角「🔦 补光 / 💡 关灯」按钮，绑定 `CameraView enableTorch`，仓库/柜台暗光下提升识别率。

## 5. 手动输入条码（#5）

- 扫码区右侧「手动输入」入口；弹窗输入吊牌编号后走与扫码**相同的查找/确认流程**（吊牌二维码破损时兜底）。

## 6. 收银议价 / 改价（#6）

- 购物车任意行点击可「改价」，修改**该行成交单价**（元），合计与结算金额实时反映；落库时按实际成交价记录（共享 `cartToSaleInput` 已逐项带 `price`）。
- 共享新增纯函数 `setLinePrice(lines, skuId, price)`（负数按 0 处理，四舍五入到分）。

## 9. 已知限制 / 后续
- 编辑页暂不支持「增删 SKU / 改颜色尺码」与改封面图，仅改名/改价/调库存与上下架；后续按需扩展。
- 议价目前为**逐行改价**，覆盖最常见的「这件便宜点」场景；如需「整单抹零/整单折扣」可在结算前再加一层分摊逻辑。
- `beep.wav` 为合成音，可后续替换为更悦耳的成品音效。
