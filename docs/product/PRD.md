## 1. 产品定位

**面向小型服装零售店（特别是"杂款"店铺）的进销存 App**。

核心场景：给每件衣服打二维码吊牌 → 收银时扫码秒匹配商品 → 自动扣库存 → 出销售报表。

一句话价值：**让软件零基础的店主，用手机就能搞定"建档—贴码—收银—看账"全流程，稳定、简单、二维码驱动。**

---

## 2. 目标用户与场景画像

| 维度 | 描述 | 对设计的约束 |
|------|------|-------------|
| 商铺规模 | 小型商铺（1～5 人），单店或少量门店 | 轻量、低成本、单店主 |
| 货品特征 | **杂款为主**（款多、单款量少、上新快、生命周期短） | SKU 多、必须**极速建档**；图像识别不适用 |
| 硬件预算 | 有限，用手机当扫描设备 | 手机摄像头扫码为主，蓝牙扫码枪/标签机为可选 |
| 操作人员 | **软件零基础** | 流程极简、按钮大、少输入、多选择、防错优于纠错 |
| 网络环境 | 仓库/店铺信号可能不稳 | **离线优先**：核心操作断网可用，联网自动同步 |
| 角色 | 店主（老板）+ 店员（员工）两种 | 权限二分（见 §6） |

> **"杂款"的本质**：高 SKU 数 + 低单款库存 + 高周转。这决定了：建档速度是核心、二维码唯一码匹配最稳、图像识别不可行。

---

## 3. 产品设计原则（不可妥协）

1. **离线优先**：核心操作（扫码、收银、开单）无网也能做，先落本地再后台同步。
2. **三步内完成**：卖一件衣服 ≤ 3 步操作（扫 → 加车 → 结算）。
3. **少输入、多选择**：尺码/颜色/品类用预置选项与模板，避免手打。
4. **防错优于纠错**：库存为 0 禁出库、重复扫码提示、删除二次确认、结算前弹确认窗。
5. **快即是稳**：扫码出结果 < 1 秒；冷启动 < 2 秒。
6. **数据可追溯**：任何库存变动都记流水，任何销售都留痕，历史账单可见图。

## 4. 核心功能清单

### 4.1 商品建档（店主，仓库端）
- 拍照建档：封面必填，可多图。
- 录入品名、品类、颜色 + 尺码（多选）、进价、售价、初始库存。
- **批量生成 SKU**：选「红/蓝」+「S/M/L」→ 自动展开 6 个 SKU。每个 SKU 自动分配**全局唯一条码**。
- 建档简化：仅"售价 + 库存"必填，品名/颜色/尺码折叠进"详细设置"。
- 款模板：常用尺码组/品类一键带入，加速杂款上新。
- 预设选项：颜色/尺码/品类/材质有常用预置（如颜色含基础色、品类含"丝巾/内裤/袜子"、材质含"皮草"等）。

### 4.2 二维码吊牌管理（店主）
- 每个自动生成**全局唯一 SKU 编号**，业务信息不入码（从数据库取，保证可更新）。
- 编号规则：10 位纯数字（新建商品采用纯数字；历史前缀+十六进制条码仍兼容可扫），查库去重 + 冲突重试。
- 蓝牙标签打印机打印吊牌（驰腾 CTPL/X1，可选）；无打印机时降级 PDF/系统打印。
- 标签排版：默认 60×40mm，二维码 + SKU 条码 + 价格；支持横向/纵向（旋转 90°）两种打印方向。

### 4.3 扫码匹配与收银（店主 + 店员，店铺端，最关键路径）
- 手机摄像头扫二维码；**本地数据库优先匹配，毫秒级、断网可用**。
- 扫中后**暂停继续识别 + 弹确认卡**（商品图/规格/价格/库存 + 数量步进器，默认 1），确认后才加入；避免持续对准自动累加。
- 兜底：手动输入条码（数字键盘），走与扫码相同的查找/确认流程。
- 收银增强：手电筒补光、扫码"嘀"声、成功/错误震动反馈。
- 购物车：逐行可改价（议价/优惠，只影响本单成交价，不改档案售价）；防超卖（按"库存 − 购物车已有"限制可加数量）。
- 整单优惠：支持"打折"（输入 8.8 = 88%）与"整单改价"，优惠按比例分摊到各行。
- 结算前弹"件数 + 总价"确认窗，防误触。

### 4.4 销售开单与出库（店主 + 店员）
- 扫码 → 购物车 → 结算 → **自动扣库存 + 生成销售单**（时间、操作人、金额、明细）。
- 落库即记录每行的**进价快照**（用于毛利计算）。

### 4.5 库存管理（店主）
- 实时库存查询、商品列表（在售/已售罄/全部）。
- 盘点：编辑商品时以"目标值"语义改库存，差额自动记 `adjust` 流水。
- 售罄自动归档、补货自动恢复、手动上下架（见 §7 业务规则）。
- **不做物理删除**（软删除），删除商品**不删任何图片**（保留历史账单可看图）。
- 库存流水全程可追溯。

### 4.6 数据与报表（店主）
- 销售流水（明细列表，含件数/操作人/规格/图）。
- 报表汇总：今日 / 本周 / 本月营业额、单数、件数、**毛利与利润率**。
- 月度历史报表：月份下拉选择（最近 12 个月），每日明细只列出有销售额的日期，点某天进入当日流水。
- 按日/周下钻 + 迷你柱状图。

### 4.7 账单编辑与删除（店主）
- 账单可改价 / 改数量 / 删单件 / 整单删除；**不支持往旧单加货**。
- 删除整单 → 回滚库存。
- 删除商品（须先售罄/下架）→ 软删除。

### 4.8 用户与门店
- 角色：店主（owner）/ 店员（staff），权限二分（详见 §6）。
- 一个门店有且只有一个注册店主；店员账号由店主在 App 内创建。
- 注册需邀请码（未配置即关闭注册）。

### 4.9 新手引导（店主）
- 店主且门店无商品时，首页展示"3 步开张"引导卡。
- 一键生成演示数据（3 款 13 SKU，幂等：已有商品不重复灌入）。
- 空状态提示（商品列表/销售记录）。

### 4.10 分发与运维（产品交付侧）
- Android App（iOS 非目标）：本地打包 APK + 公开下载页 `/download`（服务端生成二维码 + 流式下载）。
- JS/界面改动支持 OTA 热更新（免重装）；原生改动需重打包。
- 后端部署在云服务器，容器化，启动自动跑数据库迁移。

## 5. 关键业务流程

### 5.1 仓库建档
```
新增商品 → 拍照 → 选品类(模板) → 选颜色+尺码(多选)
 → 批量生成 SKU → 填售价/库存（进价可选）→ 保存 → 生成唯一条码 → (可选)打印吊牌
```

### 5.2 店铺销售（最关键路径，≤ 3 步）
```
打开App(默认进收银扫码页) → 扫 QR → 弹确认卡(默认数量1)
 → 确认加入 → 结算(弹件数+总价确认) → 库存自动扣减 + 生成销售单
```

### 5.3 离线同步
```
操作 → 写本地数据库 + 写同步队列(outbox) + 乐观扣本地库存 → 立即可继续收银
        │
   联网 → 同步引擎：先 PUSH（逐条上传 outbox）后 PULL（刷新本地目录）
        ├─ 成功 → 标记 synced
        ├─ 服务端业务拒绝(超卖等) → 标记 failed（不重试）
        └─ 网络错误 → 保留 pending（下次重试）
   关键：服务端按 opId 幂等，重发不重复扣减
```

## 6. 角色权限矩阵（产品契约，以后端强制为准）

> 设计原则：**店员只管"卖"**（能扫码、改成交价、结账，但看不到进价/利润/营业额）；**店主掌握"账与货"**；收银动作双方都能做（老板临时顶班也能收银）。

✅ 可用　❌ 不可用

| 功能 | 店主 | 店员 | 说明 |
|------|:---:|:---:|------|
| 登录 / 退出 | ✅ | ✅ | |
| 扫码收银、开单结账 | ✅ | ✅ | 店员核心工作 |
| 查看商品列表 | ✅ | ✅ | 收银需要 |
| 扫码 / 手动条码匹配 | ✅ | ✅ | 收银兜底 |
| 收银时逐行改价（议价） | ✅ | ✅ | 只影响本单，不改档案售价 |
| 整单优惠（打折/改价） | ✅ | ✅ | |
| 商品建档（新增） | ✅ | ❌ | 含拍照、定价、库存 |
| 上传/拍摄商品图片 | ✅ | ❌ | 控制图片来源 |
| 编辑商品（改名/改价/盘点） | ✅ | ❌ | |
| 商品下架 / 恢复 / 删除 | ✅ | ❌ | |
| 打印二维码吊牌 | ✅ | ❌ | 与建档配套 |
| 查看销售流水 | ✅ | ❌ | 经营数据，店员不可见 |
| 查看销售报表（汇总/毛利） | ✅ | ❌ | |
| 查看单据详情 / 编辑账单 / 删单 | ✅ | ❌ | |
| 店员管理（成员/新增） | ✅ | ❌ | |

> 注：店员能拉取商品目录（离线同步依赖），但仅用于收银，不能调用建档接口。权限以后端角色守卫强制为准；App 界面按角色隐藏入口只是体验优化，不作为安全边界。

## 7. 核心业务规则（不可违背的不变量）

这些是产品正确性的底线，任何重构都必须保留：

1. **金额一律用最小货币单位（分，整数）**：数据库、API、共享类型里的所有金额字段（进价/售价/价格/成本/小计/总额）全是分；只有 UI 展示时除以 100 显示"元"。不引入浮点元。

2. **库存只通过流水增减**：建档初始库存写入库流水、销售写出库流水、盘点/改单写调整流水。**不得直接改库存字段而不记流水**（库存字段是流水累计的物化结果）。

3. **开单/库存操作的幂等**：销售开单与库存流水带客户端生成的唯一操作 ID（opId）。离线重传同一 opId **不得重复扣减**。

4. **防超卖**：销售时库存不足必须拒绝，不得卖负。

5. **删除是软删除**：商品用删除时间戳标记（且必须先归档/售罄才能删）；订单删除会回滚库存。**删除商品不删除任何图片**（保留历史账单可看图）。永远不物理删商品/SKU，会破坏销售外键与报表。

6. **门店隔离**：几乎所有查询都要按门店过滤（从登录态取，不信任客户端传入的门店 ID）。新接口默认按当前用户门店过滤。

7. **售罄自动归档**：任意销售导致某商品总库存归零时，自动标记为"已售罄/归档"，从在售列表收起；补货（库存 > 0）自动恢复在售；店主可手动上下架。**已删除的商品不复活**。

8. **进价快照**：销售明细记录成交时刻的进价快照，用于毛利 = Σ(成交价 − 进价)，不受后续改价影响。

9. **QR 内容仅含唯一编号**：业务信息不入码（从数据库取），保证商品信息可更新而吊牌不必重打。

## 8. 非功能性需求

| 类别 | 目标 |
|------|------|
| 扫码到结果 | < 1 秒（本地匹配） |
| 冷启动 | < 2 秒 |
| 离线可用 | 核心功能（扫码/收银/开单）100% 离线可用 |
| 数据可靠 | 同步幂等、不丢单、不错扣；数据库定期自动备份 |
| 安全 | 登录态加密存储；输入校验；最小权限；门店隔离 |
| 兼容 | Android（targetSdk 兼容蓝牙打印 SDK 的广播注册行为） |
| 崩溃率 | 目标 < 0.5% |

---

## 9. 不做（明确排除，避免范围蔓延）

- 图像识别 / 以图搜款（杂款下准确率低、成本高）
- 多门店调拨 / 仓店一体（远期）
- 会员 / 营销 / 促销
- 在线收款 / 对接支付（MVP 只记账）
- 高级财务对账
- iOS 平台（当前仅 Android；蓝牙打印 SDK 仅 Android）
