# 服务器部署指南（阿里云轻量 · Ubuntu 24.04 · Docker）

面向 0 基础。全程在**阿里云控制台的网页终端**里复制粘贴命令即可，不用装任何 SSH 软件。

- 服务器：阿里云轻量应用服务器，Ubuntu 24.04，2核2G
- 部署内容：PostgreSQL 数据库 + NestJS 后端，监听 `3000` 端口
- 部署后访问地址：`http://你的公网IP:3000/api/v1`
- 代码仓库：`https://github.com/xuwj23-art/Cloth_Manager`

---

## 第 1 步：连接服务器（网页终端）

1. 登录阿里云 → 轻量应用服务器控制台 → 找到你的实例。
2. 点 **「远程连接」 / 「Workbench 远程连接」** → 用户名 `root` + 你设置的密码 → 进入黑色命令行界面。

> 之后所有命令都在这个网页终端里粘贴运行。

---

## 第 2 步：安装 Docker（用 Ubuntu 自带源 + 阿里云镜像，国内最稳）

> 不要用 `get.docker.com` 脚本——国内访问常被重置（`Connection reset by peer`）。
> 直接用 Ubuntu 软件源（阿里云镜像）安装，最稳。

整段粘贴运行（`-o DPkg::Lock::Timeout=600` 会自动等待新机开机后的后台更新锁释放）：

```bash
apt-get -o DPkg::Lock::Timeout=600 update
apt-get -o DPkg::Lock::Timeout=600 install -y docker.io docker-compose-v2
systemctl enable docker --now

# 验证：分别打印出版本号即成功
docker version
docker compose version
```

### 配置镜像加速（拉取 node/postgres 镜像更快）

```bash
mkdir -p /etc/docker
cat > /etc/docker/daemon.json <<'EOF'
{
  "registry-mirrors": [
    "https://docker.m.daocloud.io",
    "https://docker.1ms.run"
  ]
}
EOF
systemctl restart docker
```

---

## 第 3 步：拉取代码

```bash
# 安装 git（若已存在会跳过）
apt-get update && apt-get install -y git

# 浅克隆（只取最新版本，速度快）
cd /opt
git clone --depth 1 https://github.com/xuwj23-art/Cloth_Manager.git
cd Cloth_Manager
```

> 如果 `git clone` 卡住或很慢（国内连 GitHub 偶尔不稳），告诉我，我给你换成镜像加速地址。

---

## 第 4 步：填写密钥配置 `.env`

在仓库根目录生成 `.env`（数据库密码和 JWT 密钥都自动随机生成）：

```bash
cd /opt/Cloth_Manager
cat > .env <<EOF
DB_PASSWORD=$(openssl rand -hex 16)
JWT_SECRET=$(openssl rand -hex 32)
REGISTER_CODE=换成你自己的注册口令
EOF

# 看一眼（请把这三行抄下来保存好）
cat .env
```

> `REGISTER_CODE` 是「注册邀请码」：只有在 App 注册门店时填对它才能注册，防止陌生人占用服务器。
> 自己改成一串好记又不易猜的口令（如 `chenji-2026-xyz`），只告诉信任的人。想换随时改这一行再 `up -d` 即可。

---

## 第 5 步：启动后端

```bash
cd /opt/Cloth_Manager
docker compose -f docker-compose.prod.yml up -d --build
```

- 第一次会构建镜像 + 装依赖，约 3~8 分钟，请耐心等。
- 完成后查看状态：

```bash
docker compose -f docker-compose.prod.yml ps
docker compose -f docker-compose.prod.yml logs -f server
```

看到日志里出现 `服务已启动: http://localhost:3000/api/v1` 就成功了（按 `Ctrl+C` 退出日志查看，**不会**停掉服务）。

---

## 第 6 步：放行 3000 端口（关键！）

阿里云轻量默认只开放了少量端口，必须手动放行 `3000`：

1. 阿里云控制台 → 你的实例 → **「防火墙」/「安全组」** → 添加规则。
2. 应用类型：自定义；协议：**TCP**；端口范围：**3000**；授权对象：`0.0.0.0/0`。
3. 保存。

> 服务器系统自带的 `ufw` 防火墙在阿里云镜像里通常是关闭的，一般无需额外操作。若开启了：`ufw allow 3000/tcp`。

---

## 第 7 步：验证

在**服务器终端**里：

```bash
curl http://localhost:3000/api/v1/health
```

返回类似 `{"status":"ok","db":"up",...}` 即正常；若数据库不可用，该接口返回 **503**（`status:"error","db":"down"`），同时容器 healthcheck 会标记 unhealthy，便于监控告警。

然后在**你自己的电脑/手机浏览器**打开（把 IP 换成你的公网 IP）：

```
http://你的公网IP:3000/api/v1/health
```

能看到同样的 JSON，说明外网可访问，后端部署完成 ✅

## 以后如何更新后端（改了代码之后）

1. 本地：`git push`（推之前记得开代理）。
2. 服务器终端：

```bash
cd /opt/Cloth_Manager
git pull
```

## 升级到「图片压缩 + 注册码」版本时的额外动作

本版本新增：服务器端图片自动压缩 + 缩略图（依赖 sharp），以及注册邀请码。
首次升级到本版本，务必：

1. `.env` 里补一行 `REGISTER_CODE=...`（见第 4 步），否则注册会被拒绝、容器也会启动失败提示缺少该变量。
2. 重新构建并启动（会装上 sharp 图像库）：
   ```bash
   cd /opt/Cloth_Manager
   git pull
   docker compose -f docker-compose.prod.yml up -d --build
   ```

### 2G 内存加一个 swap（强烈建议）

服务器只有 2G 内存，构建或图片压缩高峰可能吃紧，加 2G swap 兜底更稳：

```bash
# 仅需执行一次
sudo fallocate -l 2G /swapfile
sudo chmod 600 /swapfile
sudo mkswap /swapfile
sudo swapon /swapfile
echo '/swapfile none swap sw 0 0' | sudo tee -a /etc/fstab
free -h   # 确认 Swap 已生效
```

### 存储评估（2 万件商品）

- 开启服务器端压缩后，每张主图约 100~~200KB、缩略图约 20KB；2 万件约 **3~~4G**。
- 当前可用磁盘约 33G，**完全够用**，长期也宽裕。
- 旧的原始大图（如有）会在重新上传时被压缩；本版本之前没有真实数据，无需迁移。

## 升级到「销售报表利润 + 日期下钻」版本时的额外动作

本版本新增：销售报表里的**毛利/毛利率**，以及今日/本周/本月的**日期下钻**（本周按天、本月按周）。
为算历史利润，给 `SaleItem` 增加了一列 `cost`（开单时的进价快照）。

- **无需手动操作**：容器启动时会自动执行 `prisma migrate deploy`，迁移会自动加上这一列。照常 `git pull` + `up -d --build` 即可：
  ```bash
  cd /opt/Cloth_Manager
  git pull
  docker compose -f docker-compose.prod.yml up -d --build
  ```
- **注意**：升级**之前**产生的测试订单没有进价快照（`cost=0`），它们的毛利会等于营业额（毛利率 100%）。正式开业前清掉测试订单即可，新订单都会正确记录进价。

## 数据库与图片备份（每日自动，强烈建议）

商品/销售等核心数据在数据库里，商品图片在 `cloth_scan_uploads` 数据卷里（「历史账单可看图」依赖它们，丢了无法恢复）。仓库自带脚本 `ops/db-backup.sh`：每日 `pg_dump` + 打包 uploads 卷 + 自动清理 14 天前的旧备份。备份目录为 `/var/backups/cloth_scan`（在 git 仓库外，避免被误提交）。任一步失败时，若配置了 `NOTIFY_WEBHOOK_URL`（企业微信/钉钉群机器人地址）会自动推送告警。

### 启用（一次性，在服务器网页终端粘贴）

```bash
cd /opt/Cloth_Manager
git pull                                   # 拿到 ops/db-backup.sh
chmod +x ops/db-backup.sh

# 先手动跑一次，确认能成功生成备份（应看到 db 和 imgs 两行 OK）
bash ops/db-backup.sh
ls -lh /var/backups/cloth_scan             # 应看到 cloth_scan_*.sql.gz 和 uploads_*.tar.gz
cat /var/backups/cloth_scan/backup.log     # 应看到两行 OK

# （可选）配置失败告警：把群机器人地址写进 root 的环境（企业微信/钉钉群机器人均可）
# echo 'export NOTIFY_WEBHOOK_URL="https://qyapi.weixin.qq.com/cgi-bin/webhook/send?key=xxx"' >> ~/.bashrc

# 加入定时任务：每天凌晨 3:00 自动备份
( crontab -l 2>/dev/null | grep -v 'ops/db-backup.sh'; \
  echo '0 3 * * * /usr/bin/bash /opt/Cloth_Manager/ops/db-backup.sh' ) | crontab -
crontab -l                                 # 确认已写入
```

> 若之前用旧版脚本备份到 `/opt/Cloth_Manager/backups`，可手动把旧备份挪到新目录留档。

### 恢复（需要时）

```bash
# 恢复数据库（会覆盖现有数据，操作前最好先手动备份一份当前状态）
gunzip -c /var/backups/cloth_scan/cloth_scan_20260611_030000.sql.gz \
  | docker exec -i cloth_scan_db psql -U cloth -d cloth_scan

# 恢复商品图片卷
docker run --rm -i -v cloth_scan_uploads:/data alpine sh -c \
  "cd /data && tar xzf -" < /var/backups/cloth_scan/uploads_20260611_030000.tar.gz
# （若服务器没有 alpine 镜像，把 alpine 换成已有的 postgres:16-alpine）
```

### 异地副本（建议偶尔做）

备份只存在同一台服务器上；万一服务器整体故障/释放，备份也会一起没。建议**偶尔把备份（库 + 图片）下载到本机**留一份（在本机 PowerShell 跑）：

```powershell
scp root@39.108.186.58:/var/backups/cloth_scan/*.sql.gz E:\Project\cloth_scan\_backups\
scp root@39.108.186.58:/var/backups/cloth_scan/uploads_*.tar.gz E:\Project\cloth_scan\_backups\
```

### 升级部署后排障

`docker compose -f docker-compose.prod.yml up -d --build` 后若 server 容器反复重启，先看日志定位：

```bash
docker logs --tail 50 cloth_scan_server
```

最常见的持久性故障是 `prisma migrate deploy` 失败（迁移 SQL 与库状态不符）：修复迁移/回滚库后重新 `up -d`。容器带 healthcheck（`/api/v1/health`），`docker ps` 里 STATUS 显示 `(healthy)` 才算真正起来了。
