## 4. 目标设计

### 4.1 首页改动（两件事）

1. 右上角 `log-out-outline` → `settings-outline`，`onPress` 从 `logout()` 改为 `navigation.navigate("Settings")`。退出入口迁至设置页底部。

### 4.2 设置页 · 店长版（SettingsScreen，新增导航路由）

**① 顶部用户卡**（沿用首页身份卡语言）：姓名首字圆形头像 + 名字 + 「老板」角色胶囊 + 店名。

**② 账号设置**（白卡列表行）：

| 行         | 形态                                | 说明                                                                 |

| 注册店铺名 | 行 + 右侧灰字显示当前店名 + chevron | 点开弹窗输入新名 → `PATCH /auth/shop` → 重拉 `me` → 首页店名即时更新 |
| 手机号     | 只读行                              | 右侧灰字显示，无 chevron，副注「登录账号，不可修改」                 |

**③ APP 设置**：

| 行       | 形态                                 | 说明                                                                                                                                                 |
| -------- | ------------------------------------ | ---------------------------------------------------------------------------------------------------------------------------------------------------- |
| 打开通知 | Switch                               | 语义对应「新结账提醒」总闸：开启时挂载 `useOwnerSaleAlerts`（现状休眠代码，见 §5）+ 请求系统通知权限；拒绝时点击引导跳系统设置                       |

### 4.3 设置页 · 店员版

**① 顶部用户卡**：同上（「店员」胶囊）。

**② 账号设置**：

| 行       | 形态                              | 说明                                                         |
| -------- | --------------------------------- | ------------------------------------------------------------ |
| 修改名字 | 行 + 右侧灰字显示当前名 + chevron | **店员唯一可编辑项** → `PATCH /auth/me{name}`，改后重拉 `me` |
| 密码     | 只读行                            | ⚠️ 见下方「显示密码」冲突                                    |

**③ APP 设置**：版本号 + 检查更新（同店长）。**无通知开关**——当前无任何店员侧通知业务（§5），将来若开放「新结账提醒」给店员再加。

**④ 底部**：退出登录（同店长）。

> ### ⚠️ 「显示密码」的技术冲突（待店主拍板）
>
> 数据库只存 **bcrypt 哈希**，「让店员看到自己的密码」在现有存储下**技术上不可能**。三个选项：
>
> - **A（推荐）**：密码行显示固定文案「密码由店主管理，如需修改请联系店主」，配锁形图标。零后端改动，密码安全策略不变。
> - **B（不推荐，但可行）**：密码改为**可逆加密存储**（AES-GCM + 服务端密钥），新增「查看密码」接口（仅本人）。代价：token 泄露即可看明文密码、撞库风险扩大、存量 bcrypt 密码无法迁移只能全员重置。为小店便利牺牲安全底线，需要店主明确接受才做。
> - **C**：登录/改密输入框的明文切换（眼睛图标）——那是输入体验，不是「显示密码」功能，只作为附带优化。
>
> 若店主本意是「店员忘了密码能自己看一眼」，A 的替代闭环是：店员设置页放「忘记密码？联系店主重置」提示，店主在店员管理页 10 秒重置。

### 4.4 应用内更新机制（v3 定稿：二级进度界面 + 自动重启）

**检查更新入口**（设置页「检查更新」行）逻辑不变：manifest 版本 > 当前 → APK 流程；否则查 OTA。两条提示互斥。

**更新二级界面（UpdateSheet，v3 核心）**：进入检查后弹出底部弹层，完整生命周期：

```
┌────────────────────────────┐
│  ↻  正在检查新版本…          │  态1 检查中（spinner）
├────────────────────────────┤
│  ✓ 已是最新版本 v1.5.0       │  态2 无更新（图标+灰字，2s 后自动收起）
├────────────────────────────┤
│  新版本 v1.6.0              │  态3 有更新：版本号大字
│  · 新增设置中心…（更新说明）   │      current.json notes
│  ▓▓▓▓▓▓░░░░░ 46%  12.3MB   │      下载进度条 + 百分比 + 已下载/总量
│  [ 立即更新 ]                │      主按钮：下载中变「下载中 46%」禁点
└────────────────────────────┘
```

- **OTA 分支**（纯 JS 更新）：`fetchUpdateAsync()`（spinner 显示「正在下载更新…」，通常数秒）→ 完成后按钮变「重启生效」倒计时 3 秒自动 `reloadAsync()` **自动重启 App**（不强制用户手点；也保留手动按钮）。OTA 无官方进度回调，用不定进度条/spinner。
- **APK 分支**（原生更新）：`expo-file-system` 可断点下载（`createDownloadResumableAsync` 有 `progress` 回调 → 真实百分比进度条）→ 下载完成自动 `expo-intent-launcher` 拉起系统安装器（`application/vnd.android.package-archive`，`FLAG_GRANT_READ_URI_PERMISSION`）；用户点「安装」后系统完成升级并自动打开新版（即"自动重启"）。失败可重试（断点续传）；取消安装回到弹层可再次拉起。
- **兜底**：拉起安装器失败（国产 ROM 限制「未知来源」）→ 弹层内出现「去下载页手动安装」链接（Linking → /download）。
- 网络异常：显示错误 + 「重试」。

依赖与代价：`expo-file-system` + `expo-intent-launcher`（原生依赖，本期重打 APK 正好一并带上）；`app.json` 增加 `REQUEST_INSTALL_PACKAGES` 权限；首次使用安装器时部分 ROM 需在系统设置允许「安装未知应用」（IntentLauncher 会带出引导）。

## 5. 通知与弹窗现状（澄清问题 6 的调研结论 · v3 修正版）

### 5.1 现状事实

**结论：新结账提醒功能当前就是启用状态**——挂在 `apps/mobile/App.tsx` 的 `AuthedApp`（`useOwnerSaleAlerts(user?.role === "owner", user?.id)`），老板机前台时弹居中 AppDialog + 声音，退后台时收系统通知栏横幅（「结账提醒」渠道、HIGH 优先级、声音+震动）。1.3.0 店主实测听到的提示音即来源于此，行为一直如此。

> ⚠️ 勘误（v2 曾误判）：v2 调研时 grep 只扫了 `apps/mobile/src/`，而挂载点在仓库根部 `apps/mobile/App.tsx`，因此误判为「休眠代码、从未挂载」。v3 重新核对后更正：**功能一直在线**。店主「当时没看到弹窗」大概率是老板机在后台/锁屏（走的是通知栏而非界面弹窗），或弹窗被随手关掉。

| 问题               | 事实                                                                                                                         | 依据                                             |
| ------------------ | ---------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------ |
| 有远程推送吗       | 没有。后端无推送服务；App 退后台靠本地轮询发系统通知，**进程被杀后收不到**（代码注释：国内无可靠免费远程推送，按约定暂不做） | `src/notify/saleAlerts.ts:49`                    |
| 有本地通知吗       | 有，启用中：`useOwnerSaleAlerts` 每 20 秒轮询销售流水，发现**非本人**新单 → 前台弹 AppDialog+声音；后台发系统通知            | `App.tsx` AuthedApp + `src/notify/saleAlerts.ts` |
| 现有前台弹窗的问题 | 用的通用 `notice`（居中 AppDialog，**需手点确定才消失**），老板正在扫码/看报表时会被打断——这是 v3 要重设计的点               | `saleAlerts.ts` notifySale                       |
| 通知权限           | `POST_NOTIFICATIONS` 已声明，hook 挂载时自动请求                                                                             | `saleAlerts.ts:66-67`                            |
| App 内其他弹窗     | 全自研：`dialog-context` confirm/notice + 14 个业务 Modal/Sheet；0 处系统 `Alert.alert`，无 toast                            | grep 全 src                                      |

### 5.2 v3 改造内容（新结账提醒）

1. **前台提醒重设计**：把打断式的居中 AppDialog 换成**顶部滑入提醒卡（NewSaleToast）**——顶部安全区下滑入，金点 +「新结账」+ 金额大字 + 「N 件 · 操作人」副行，5 秒自动滑出，点击跳报表流水；220ms 动画，不遮挡底部操作区。前台时**不再发系统通知**（避免横幅+弹窗双重打扰）。
2. **退后台/锁屏**：维持系统通知（声音+震动），与 1.3.0 体验一致。
3. **通知开关**（设置页 · 仅店长）：控制本功能总闸，默认开（保持现状）；关闭后轮询静默、不再提醒。持久化到 SecureStore。
4. **真实测试**（模拟器双角色）：店员开单 → 老板机前台弹 Toast 卡片、退后台收系统通知 + 声音；开关关闭后无提醒。

### 5.3 前台提醒弹窗设计（v3 新增）

现状 `notifySale` 用通用 `notice("新结账", body)`（AppDialog 居中卡），信息层级一般。重构为**顶部滑入式提醒卡（NewSaleToast）**：

- 顶部安全区下滑入，金点 +「新结账」标签 + 金额大字（primary）+ 副行「N 件 · 操作人」；5 秒后自动滑出，点击可跳报表流水；
- 动画 220ms（与全局 motion token 一致），不遮挡底部操作区；
- 退后台/锁屏时走系统通知（声音+震动，渠道「结账提醒」），这是 1.3.0 已验证的路径，保持不变。

## 6. 店员管理页重构（澄清问题 5）

### 6.1 现状痛点（`StaffScreen.tsx`）

1. 新增店员表单**常驻列表头**（3 输入框 + 按钮顶在最上面），页面拥挤，与「查看成员」主任务互相干扰；
2. 每个成员行行尾堆**两个文字按钮**（修改密码/删除），密度高、误触风险大、红色删除随手可点；

### 10.3 重要实测结论：后台提醒的真相

Android 退后台/锁屏后，**JS 轮询会被系统暂停**（dev 包与 release 包实测一致，48 秒零轮询；通知渠道/权限本身正常）。即原代码注释宣称的「退到后台但进程仍存活时仍会提醒」从未真正成立——1.3.0 老板听到的提示音是**前台场景**（手机亮屏开着 App）。

本期落地策略：前台 Toast + 退后台瞬间补一次轮询 + 回前台补发期间新单；长时间后台无法提醒（需远程推送，按约定暂不做）。代码注释与 AGENTS.md §10 已如实记录。
