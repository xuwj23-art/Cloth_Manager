## 文档权威等级（重要）

重构后文档按**权威性分三层**。冲突时按上层优先：

```
① 产品权威层  >  ② 操作手册层  >  ③ 历史归档层
   PRD.md          部署/自检清单       archive/
```

| 层 | 含义 | 重构时是否约束技术选型 |
|----|------|----------------------|
| ① **产品权威** | 产品是什么、给谁、要什么功能、业务规则 | ❌ 不约束（技术无关） |
| ② **操作手册** | 当前部署/打包/验收的事实步骤 | ✅ 描述现状，改了要同步 |
| ③ **历史归档** | 旧规划/阶段设计，仅供溯源 | ❌ 不约束（产品部分已被 PRD 取代，技术部分不再权威） |

## 重构时的文档使用原则

1. **产品需求看 PRD**：要做什么、业务规则、权限矩阵——以 `product/PRD.md` 为准。
2. **技术选型自由重估**：PRD 刻意技术无关；`TECH-NOTES.md` 是出发点不是约束。
3. **历史文档仅供溯源**：`archive/` 里的技术决策不约束重构，只回答"为什么当初这么选"。
4. **改了代码要回写**：当代码与 PRD/TECH-NOTES 冲突，以代码为准并回头修正文档。
